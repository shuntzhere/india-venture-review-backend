## Technical Decisions

**Word boundary regex over substring matching**
The original implementation used `keyword.lower() in title_lower` — a simple substring check. This can match keywords inside unrelated words: `"round"` would match `"surrounding"` and `"background"`, `"backed"` would match `"setback"`. The replacement uses `re.search(r"\b" + re.escape(keyword) + r"\b", title, re.IGNORECASE)`. The `\b` anchor matches at the boundary between a word character and a non-word character, ensuring only standalone word occurrences are matched. `re.escape()` ensures keywords with special characters like `"Pre-Seed"` are treated as literals rather than regex operators.

**`"investment"` removed from the keyword list**
During Step 3 validation, `"investment"` matched `"Zerodha eyes investment banking with SEBI merchant banking licence"` — clearly not a funding event. The word appears in non-funding contexts (investment banking, divestment strategy, investment-grade ratings) far too frequently to be a reliable signal. Actual startup funding events that use this word almost always also contain `"raises"`, `"funding"`, or `"round"`, which are already covered. The removal reduced false positives with negligible recall loss.

**`"bags"` added to the keyword list**
Confirmed in Step 3 validation output: `"The Capitalist Ventures bags Rs 10 Cr seed round"` was the first article in the feed and is a clear funding announcement. `"bags"` is common in Indian startup funding reporting vocabulary and is specific enough to not cause false positives.

**HTML cleaning with `html.parser` rather than regex**
The `raw_content` returned in Step 3 contained raw HTML (e.g. `<img src="...">` fragments from the RSS `<content>` element). Step 4's parser will need clean text. Stripping HTML with regex is fragile: it breaks on nested tags, self-closing elements, HTML entities, and malformed markup. Python's built-in `html.parser` handles all of these correctly via a subclassed `HTMLParser` that collects text nodes. No new dependency was required.

**URL deduplication**
RSS feeds can occasionally publish the same article more than once — on correction, re-syndication, or feed regeneration. Without deduplication, the same article could appear twice in the returned list, potentially causing a duplicate insert in the database in Step 5. A `seen_urls` set before the main loop guards against this. The cost is negligible.

**HTTP User-Agent header**
Some servers treat requests without a User-Agent header as suspicious and may throttle or block them. Identifying our scraper with `"IndiaVentureReview/1.0 (+https://github.com/shuntzhere/india-venture-review)"` follows standard HTTP client practice and makes our traffic identifiable in Entrackr's server logs. Defined as a module-level constant (`HTTP_HEADERS`) so it is easy to update in one place.

**`verbose` flag preserves silence in production**
The diagnostic output is gated behind `verbose=False` (the default). When the module is called by the pipeline in Step 7, it is completely silent. When run directly for testing (`python3 -m scraper.entrackr`), verbose output is automatically enabled via the `if __name__ == "__main__"` block. The same function works correctly in both contexts without any branching in the caller.

**Public behaviour preserved**
The function name `fetch_entrackr_articles()`, its return type (list of dicts), its field names, and the manual validation command (`python3 -m scraper.entrackr`) were all kept identical. This was an explicit constraint because Step 4's parser will import and call this function directly. Breaking the interface at this stage would require rework in a module not yet built.
