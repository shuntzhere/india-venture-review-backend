# Step 7.1 — Independent ingestion fallback

Vercel hosting suspension stopped daily ingestion while Supabase remained
available. The backup executes the pipeline directly from GitHub Actions after
checking the most recent primary schedule's durable SUCCESS record.

The runner shares ingestion locking and source/event duplicate detection with
the hosted pipeline. Freshness is rechecked under the lock. Missing telemetry
fails closed; completion is verified before reporting success. The process group
is terminated at 240 seconds, before its 330-second lease expires. A later run
can retry partial work. Optional AI website enrichment is deferred.

## Migration record

The release supplies sql/add_ingestion_runs.sql and the separate additive
sql/add_ingestion_run_metrics.sql. The production table and metrics columns were
installed on 22 November IST. Existing ingestion lock, funding-source and company
identity schema are prerequisites; this release does not automatically execute
SQL or unrelated reconciliation scripts. The historical schema dependencies are
included for review and existing regression tests.

## Security and activation

Actions are pinned to commit IDs and Python dependencies to versions and hashes.
A test job has no production secrets. The production job is restricted to the
default branch and environment ivr-ingestion-backup; the environment's saved
branch rule allows main only. No database credential has been copied to GitHub.
The service-role key is project-wide, not a least-privilege identity. Provisioning
it requires owner approval. Main has not been merged or deployed.

## Validation

74 tests pass in an isolated checkout on Python 3.12. Hash-locked dependency
installation succeeds. A controlled local production run read 50 RSS entries,
persisted SUCCESS with no new events, and a repeat history check returned
SKIPPED_FRESH. An initial history-read timeout failed without data writes.

The separate 19–21 November sitemap backfill was previewed and then applied:
five companies and five confirmed funding events were inserted, with zero
extraction/database errors or event conflicts. Read-back verification follows
in the task's operational records.

## Limitations and rollback

The 48-hour RSS window cannot guarantee older outage recovery. GitHub schedules
may be delayed or disabled for inactivity. Failure notifications must be enabled
in GitHub; a failing check alone is not proof of email delivery. The backup does
not restore the website or run source-discovery AI. Disable the workflow to
stop future backups; existing Supabase records remain.

See docs/fallback-ingestion.md for the activation procedure.

## Partial-day outage correction

A follow-up audit found that the 18 November primary run preceded three later
announcements: Humyn Labs, Botsync and Fatehpuria Hygiene. The original
19–21 November recovery range did not cover that partial day. The 18 November
dry-run identified three missing confirmed events and two existing duplicates,
with zero extraction or database errors. The apply pass inserted all three missing events, skipped the two duplicates,
and reported no extraction/database errors or event conflicts. Read-back
verification covers eight recovered events and eight source links in total.
Entrackr’s live sitemaps for 20 and 21 November list a Rooter financial-results
article and a weekly roundup respectively; neither is a standalone new round.
