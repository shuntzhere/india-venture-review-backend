## Technical Decisions

**Numbered file convention for `docs/implementation/`**
Implementation history documents use a numeric prefix (`01_`, `01.1_`, `02_`) rather than dates or sequential integers. This allows sub-steps to be inserted between major steps without renaming existing files, and preserves a readable build order.

**`docs/`, `sql/`, `tests/` added early**
These folders were created before any code requiring them existed. Establishing structure early prevents ad-hoc file placement as the project grows and signals clear boundaries: database files go in `sql/`, tests in `tests/`, documentation in `docs/`.

**`PROJECT_ARCHITECTURE.md` as a living document**
The architecture document was written to be updated whenever the project structure changes significantly. It is not a one-time snapshot — it is the authoritative technical reference for the project.

**`CHANGELOG.md` follows Keep a Changelog convention**
Entries are organized under version numbers with a date and categorized as Added / Changed / Fixed. An `[Unreleased]` section is maintained at the top for work not yet tagged.

**`TODO.md` organized by horizon**
The backlog is split into In Progress / Up Next / Backlog / Future to distinguish immediate next actions from long-term aspirations. This prevents the document from becoming a flat list with no sense of priority.
